CCT PAGE — FRONTEND REACT + TYPESCRIPT + VITE
=============================================

ESTA ES LA UNICA CARPETA DEL PROYECTO.
No vuelvas a ejecutar git clone dentro de CCT-PAGE.
No crees archivos v2, final, copia, backup, old, etc. dentro del codigo activo.

PARA RETOMAR EL PROYECTO
------------------------
1. Abre CMD o PowerShell.
2. Entra a tu carpeta CCT-PAGE.
3. Ejecuta:

   git pull
   npm ci
   npm run dev

4. Abre la direccion Local que muestra Vite (normalmente http://localhost:5173/).

Tambien puedes hacer doble clic en INICIAR_CCT.bat.
El proyecto esta estandarizado en Node.js 24.x.

FUENTES ACTIVAS DEL FRONTEND
----------------------------
- src/App.tsx: composicion principal.

- src/components/AppErrorBoundary.tsx: evita una pantalla blanca si React falla durante el render.
- src/pages/<pagina>/markup.html: markup canonico de cada vista.
- src/layout/: header, footer y modales globales.
- src/features/home/career.ts: Conoce tu carrera de Inicio.

- src/features/nosotros/nosotros.ts: Nosotros.
- src/features/formation/formation.ts: Formacion + Academias.

- src/features/community/community.ts: Comunidad.
- src/features/events/events.ts: Eventos.
- src/features/shared/ui.ts: comportamientos compartidos.
- src/styles/sections/: CSS canonico por seccion.

REGLAS PARA CAMBIOS NUEVOS
--------------------------
1. Imagen simple:
   consulta IMAGE_MAP.md y reemplaza el mismo asset conservando nombre y extension cuando sea posible.

2. Cambio visual de una seccion:
   modifica el markup canonico y/o el CSS canonico de ESA seccion.

3. Interaccion o componente NUEVO:
   debe hacerse en React/TypeScript. No agregues nuevos onclick inline, nuevos bloques innerHTML,
   scripts globales ni codigo a site.js.

4. Una seccion tiene un solo dueño.
   Nunca crear otra implementacion para no tocar la anterior.

5. Antes de fusionar cualquier cambio:

   npm run check:all

VERIFICACIONES AUTOMATICAS
--------------------------
- check:frontend: impide que crezca el legacy, valida seguridad basica, assets y limite React/HTML.
- check:architecture: valida owners, vistas, rutas internas y archivos prohibidos.
- TypeScript strict.
- Vite build.
- check:dist: valida exactamente lo que se publicara.
- check:browser: abre Chrome real, prueba las 7 vistas, una ruta inexistente y Open Course.
- GitHub Actions ejecuta estas comprobaciones antes de integrar cambios.
- GitHub Pages no despliega si la prueba de navegador falla.

IMPORTANTE
----------
El HTML estatico aprobado se mantiene temporalmente como plantillas por vista para conservar exactamente
la apariencia actual. React lo monta solamente mediante TrustedStaticShell. La migracion futura a JSX debe
hacerse por seccion y con pruebas, no mediante una reescritura masiva que arriesgue el diseño.
